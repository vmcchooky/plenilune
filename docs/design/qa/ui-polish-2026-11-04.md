# UI polish pass · 04/11/2026

Implemented in the new worktree `D:\Quorix\ui-polish-20261104` on branch
`feat/ui-polish-cream-20261104`, cut from `origin/main` (119e91d). The owner
reported, from running captures: controls sitting on hairline rules, tight
padding, an OS-themed dropdown popup, narrower widths where space is needed,
and awkward line wrapping. This pass addresses those without touching the
engine, contracts, wire schemas, palette or the light-only scheme.

## What changed

### Palette-synchronized primitives (P1)
- `components/Select.tsx`: accessible listbox replacing every native `<select>`
  (sample band, condition kind, watch domain, region protocol). The popup
  uses `--surface`/`--line`/`--radius-md` with an `--accent-soft` selection
  and check mark; flat, no shadows. Keyboard contract: ↑/↓, Home/End,
  Enter/Space, Escape, cyclic typeahead from the closed state; focus stays
  on the trigger with `aria-activedescendant`; click-outside closes; the
  popup flips above the trigger near the viewport bottom; coarse pointers
  get 44px options. 5 unit tests (`tests/select.test.tsx`).
- `components/FileField.tsx`: the real file input stays `sr-only` and
  label-associated; the visible control is a secondary button plus the file
  name/size (or the localized "no file" hint). Replaces the three native
  inputs in `OfflineReviewPanel` ("Nhập hồ sơ để phát lại").
- `:focus-visible` and disclosure `summary` now share the control corner
  radius — the square dark outline on "Phần cấu hình ngoài phạm vi phân
  tích" is gone.
- `summary` elements get `border-radius: var(--radius-sm)` globally.

### Spacing and rhythm (P2)
- `.record-refined__details` gains padding so "Xem toàn bộ thay đổi & kết
  quả kiểm tra" no longer sits on the card border.
- Rule lines always keep generous air on both sides: `.action-bar`
  padding-top 24px, `.quick-screen` gap 24px, `.review-disclosure`
  padding-top 24px. (Two attempts were judged off: 12px + a
  `.quick-screen > .review-disclosure { padding-top: 0 }` override read as too
  tight; 32px then read as too far apart. The "quá xa" look was actually a
  dead `.quick-sources` strip — border + padding around nothing while the
  sources panel was collapsed — now hidden as a whole. Both sides of every
  disclosure hairline carry 24px.) Open panels breathe 12px
  under their toggles.
- Disclosure panels no longer repeat their toggle's label visibly (e.g. chat:
  toggle "Hỏi về kết quả này" then panel heading with the same words); the
  visible heading is now `sr-only` via `SectionHeading srOnlyTitle` while
  `aria-labelledby` stays intact. Deep-mode ChatPanel heading unchanged.
- Watch form: 16px inset, 16px gaps, fields flex-basis 240px; empty state
  is a flex column with 24px padding and a 16px gap (button fully separated).
- `.action-bar` and empty-state card now match the 8/16/24 rhythm.

### One rail, no cramped wrapping (P3)
- The quick verdict screen spans the same `--max-main` rail as deep review.
  The `.quick-screen` 58rem cap, the 720px `.quick-outcome.record-refined`
  cap, and the `.workspace--quick` watch-drawer/mode-bar/error-panel caps are
  removed (supersedes the 02/11 F14 width decision on the owner's 04/11
  feedback; the token remains for the `?design=` studies).
- Download grid: items get `min-width: 0`, labels wrap with `break-word`
  (no more one-word-per-line), symmetric padding, divider kept.
- Witness selector: hash and packet are `nowrap` + ellipsis with the full
  value in `title`; the label wraps normally.
- Prose/headings get `text-wrap: pretty|balance`; `preview`/`pretty` kept
  out of code blocks.

### Harness
- `tests/review-desk-browser.mjs`: `selectOption('blank')` → click the
  trigger, then the option (the native select no longer exists). No
  assertion was weakened. `tests/p18quick.test.tsx` picks the sample option
  the same way; one SCREENSHOT-less flow assertion retained.

## Flow review · 04/11/2026 (post-polish)

- INCONCLUSIVE comparisons are not a dead end: the deep result screen keeps
  a "Thử lại với ngân sách mặc định" action whenever the verdict is
  inconclusive (it re-runs the comparison with default budget and clears the
  option override). Verified in code (`compareWithDefaultBudget`, ResultStep
  `canRetryDefault`) and by the budget-sample walkthrough.
- `classifyScope` runs after the comparison is published and staged; if it
  throws (binding failure), the user sees a top-level error panel while the
  comparison itself remains visible — a partial failure is presented as a
  total failure. Accepted for now because it only occurs on genuine binding
  breakage; noted here rather than masked.
- Deep rail: `canResult`/`canEvidence` now accept analysis-only sessions
  (prefix-list and unsupported flows), matching `navigate()` and the
  AnalysisOnly views; the rail no longer disables the stage the user is on.
- Sources panel in quick mode cannot be collapsed once opened (one-way
  reveal). Recorded as a known P3 nit, not a regression; a close/toggle is a
  separate design decision for the owner.
- INCONCLUSIVE keeps the primary CTA enabled on the quick record; the
  accept path yields INCONCLUSIVE obligations and `Nhận để review` stays
  locked, so the path is exploratory by design (owner chose not to gate it).

## Deep flow walkthrough · 04/11/2026

- Full path exercised end to end: source → result → policy accept →
  comparison (OB-1 failed, OB-2/3 held) → repair (removed the deny rule) →
  receipt VERIFIED → "Nhận để review" → evidence (10 downloads, 2 replay
  actions, replay matched) → decision stale check.
- Editing the repair after a decision clears the receipt and hides the
  decision section; a top-level stale banner explains why. Re-verifying
  restores the section with the stale status and keeps "Nhận để review"
  disabled while an obligation fails. No silent loss of the decision.
- Budget INCONCLUSIVE → "Thử lại với ngân sách mặc định" re-ran to
  DIFFERENT, cleared the option override, and removed both the source
  budget note and the retry action. Verified in the browser, not only in
  code.
- Offline import/replay (CLI-generated evidence/v2 plus both ACLs): the
  three FileFields show name and size, replay returns
  `COMPARISON_REPLAYED`. Replay actions in `.replay-tool` (offline import,
  analysis evidence, comparison evidence) used to stretch to the whole
  column because both containers are flex columns; they now keep their
  intrinsic width (120–215px) in an action row. The analysis replay title
  was an `h2` inside a grid whose sibling columns are `h3`; quick evidence
  now passes `headingLevel={3}` so both columns share the 14px column
  heading, while standalone analysis evidence keeps its section `h2`.
  Captures `deep-15/18/22/23`, `quick-26/27`.
- Inbox: add/remove watch via the custom Select and checkbox group works;
  axe 0 with the drawer and add form open at 1440px.
- Packet probe: "Thử gói này" opens the probe details, moves focus to the
  first field and evaluates both versions; an out-of-range port shows the
  Vietnamese validation copy (0–65535) without a network call. Deep repair
  receipt technical details render hashes, status and the raw repair JSON
  intact after the disclosure change.
- Chat (artifact-anchored): preset questions fill the input only; asking
  posts the exchange inline and the deterministic answer lists facts with
  their artifact field names. AI phrasing is off by default and the toggle
  is honest about it.
- Review decision: "Nhận để review" stamps the receipt digest; the stale
  path (edit → verify → stale banner → blocked receive) is exercised in
  the browser and matches the hook's `canReceive`/`invalidateDecision`
  contract.
- Repair operations: replace, add-before and append all add labeled edits
  to the draft; removing a draft edit re-enables its row. Five-edit cap
  and duplicate-line guard are visible in the edit list; the in-draft
  rows are marked and disabled.
- Quick evidence after a decision: the quick path's accept-compare-repair
  works without any accept checkbox (the "Chấp nhận & kiểm chứng" button
  commits directly in quick mode), and the evidence drawer renders the
  same translated report, replay columns and download grid as the deep
  stage. The markdown download carries the review decision section; the
  visual report intentionally does not — the decision block lives under
  the report in both modes.
- Verdict plate, change classes, witness detail and the comparison
  details disclosure render without layout regressions at 1440px; the
  sticky topbar shadow on full-page captures is a viewport artifact,
  not a DOM duplicate (single `.topbar` confirmed).
