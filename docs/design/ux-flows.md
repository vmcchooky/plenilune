# Review desk flows

1. Sample / paste / import before and after → existing debounced local analysis →
   verdict + object overview → inspect source pair. Errors retain editable sources.
2. Choose object → expand conditions → edit → normalized policy preview → explicit
   acceptance → deterministic verification. No acceptance is inferred from collapse.
3. Deep review → source → result → conditions → candidate → verify → human decision
   → evidence/export. Existing navigation and stale guards remain authoritative.
4. Expand watches → inspect notifications / configure watches → collapse. The main
   review remains mounted; switching quick/deep shares the same review state.

Desktop: heading → [verdict | object overview] → [before | after] → optional policy
→ evidence → questions. Mobile stacks both pairs in that same reading order.
Empty entry has no result grid and leads with the source editors.

## Quick-path reading burden · owner feedback, 02/11/2026

For the single ACL SSH sample, entry is now one concise outcome: an explicitly
labeled packet example, its before/after action and the deciding proposed rule.
The first actions expand intent verification or source editing, with keyboard
focus moved to the requested section. A single optional tools disclosure contains
object overview, sources, conditions, evidence and questions; blank input keeps
sources open. Multiple objects and unsupported input expose the selection tools.

Incomplete/truncated results and configuration coverage gaps stay outside collapsed
details. A witness remains a point example; no number of edited lines determines
semantic scope. More change groups are announced and the full class list remains
available under verification details. Backend acceptance/replay/repair contracts
are unchanged.

## Notification arrival, 03 November 2026

The watch drawer now keeps its component and draft mounted when unread counts
change. In quick mode it stays after the result; an explicit unread action in the
mode bar opens and focuses it. This prevents asynchronous arrival from closing the
drawer, erasing an in-progress watch name or moving keyboard focus. The browser
regression covers typing → notification → jump → mark all read, VI/EN at four
widths. Inbox responses are controlled fixtures; analysis uses the local engine.
