Codex reproduced the issue before changing code: 4/6 new tests failed.

- `web/src/components/PacketRoute.tsx` now renders `srcPort === null ? t('packet.notTcp') : ':' + srcPort`,

  áp dụng" / "Not applicable". This matches CONTRACTS.md (numeric witness port
  is a concrete value, not the ACL wildcard).
- New regression tests: `web/tests/packet-route.test.tsx` (VI + EN, protocols 6/17,
  zero and nonzero ports, ICMP inapplicable) and an explicit zero-destination
  case in `web/tests/record-composition.test.tsx` asserting the example contains
  `192.0.2.10:0` and **does not** contain "(any)".
- Current gate: `npm test` **22 files / 182 PASS** (run 10:22, local working tree).
- No remaining `packet.any` usage; "any" only appears for actual ACL wildcard
  regions, not for witness ports. **Verdict: fixed correctly, no assertion
  weakened.**

## 2. InboxPanel remount on unread — CONFIRMED and correctly resolved

Codex's own reproduction: with a pending inbox response, an unread arrival
remounted the drawer, closed it, erased `DRAFT-ACL` and dropped focus.

- `web/src/App.tsx` now renders `watchDrawer` from a stable `key="watch-drawer"`
  element and no longer swaps parents when unread changes. Unread is surfaced
  via a quiet action in the mode bar that opens the drawer, focuses the summary
  and scrolls to it — notifications are visible without reordering work.
- Regression test `p18quick.test.tsx` ("preserves the open watch draft and focus
  when unread notifications arrive") asserts the same drawer DOM node survives,
  `name.value` remains `DRAFT-ACL`, focus stays on the name input, and
  `listInbox` is not re-fetched. **Verdict: fixed correctly; watch draft and
  focus are preserved.**
